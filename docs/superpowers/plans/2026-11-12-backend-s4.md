# Backend SKPI (S4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Backend Express + fabric-gateway + PostgreSQL yang memenuhi kontrak API frontend sehingga `httpClient.ts` bekerja tanpa diubah.

**Architecture:** Layanan bergantung pada dua antarmuka: repositori PostgreSQL (satu implementasi, diuji dengan Postgres nyata di Docker) dan `Ledger` (implementasi gateway nyata + `FakeLedger` yang meniru 8 fungsi chaincode untuk test). Proyeksi aset di PostgreSQL diperbarui dari nilai kembalian transaksi; detail dan verifikasi dibaca ulang dari ledger.

**Tech Stack:** Node 22, TypeScript 5.9, tsx, Express 5, @hyperledger/fabric-gateway 1.x, @grpc/grpc-js, pg, node-pg-migrate, zod, pino, jsonwebtoken, cookie-parser, express-rate-limit, @node-rs/argon2; mocha, chai, sinon, supertest.

**Spec:** `docs/superpowers/specs/2026-11-12-backend-s4-design.md` (kontrak API: `docs/superpowers/specs/2026-11-10-frontend-skpi-design.md` §6, `docs/superpowers/specs/2026-11-11-pejabat-penanda-tangan-design.md` §4, bentuk data: `frontend/src/api/types.ts`).

## Global Constraints

- Semua respons dan body mengikuti `frontend/src/api/types.ts` dan `frontend/src/api/httpClient.ts` (pembungkus `{user}`, `{draft}`, body draft datar, `{candidates, truncated}`).
- Galat: `{ "error": { "code": string, "message": string } }`, kode HTTP 400/401/403/404/409/429/502/503; pesan Bahasa Indonesia; tanpa stack trace, path wallet, isi sertifikat.
- Nama fungsi chaincode tetap: `SahkanDekan`, `SahkanRektor`, `TolakRektor`, `PerbaruiSKPI`, `CabutSKPI`, `VerifikasiSKPI`, `BacaSKPI`, `RiwayatSKPI`.
- Nilai lingkungan hanya dari `.env`; `.env.example` diperbarui setiap ada variabel baru.
- Query selalu berparameter; perubahan skema hanya lewat `backend/migrations/*.sql`.
- Status draft internal `MENUNGGU_KONFIRMASI` dikeluarkan ke API sebagai `MENUNGGU_DEKAN` (tipe frontend tidak mengenalnya); approve atas draft itu → 409 "Transaksi sebelumnya masih menunggu konfirmasi ledger."
- Test dijalankan dari PowerShell dengan path `C:\...` (kejanggalan huruf drive di Windows).

## Review Focus

- Transaksi ledger timeout setelah submit → draft tidak boleh `DISETUJUI` maupun kembali bebas disetujui ulang; rekonsiliasi menyelesaikannya (Task 6, Task 9).
- Dekan FT mencoba approve/reject draft FMIPA, atau admin FT membuat draft NPM FMIPA → 403, tidak ada panggilan ledger (Task 6).
- Peer mati saat `/verify/:npm` atau `/ledger/info` → 503 `UNAVAILABLE`, bukan data proyeksi (Task 7).
- Login dengan NIP/NIDN/email ber-spasi/huruf besar, akun nonaktif, sandi salah → pesan seragam "Email atau kata sandi salah." (Task 3).
- Pencarian nama dengan `%`/`_` atau < 3 huruf → tidak menjadi wildcard SQL; 400 untuk < 3 huruf (Task 7).

### Task 4: Antarmuka Ledger, FakeLedger, pemetaan galat

**Files:** Create `backend/src/fabric/{ledger,errors,gateway,qscc}.ts`, `backend/test/helpers/fakeLedger.ts`, `backend/test/unit/fabricErrors.test.ts`, `backend/test/unit/fakeLedger.test.ts`.

**Produces:**
```ts
interface Ledger {
  submit(identity: string, fn: string, args: string[]): Promise<{ txId: string; result: string }> // commit sudah sukses
  evaluate(identity: string, fn: string, args: string[]): Promise<string>
  chainHeight(): Promise<number>
  txStatus(txId: string): Promise<"COMMITTED" | "INVALID" | "UNKNOWN">
  close(): Promise<void>
}
class LedgerError extends Error { kind: "REJECTED" | "UNAVAILABLE" | "COMMIT_UNKNOWN"; txId?: string }
function toApiError(e: unknown): ApiError
```
`gateway.ts`: satu koneksi gRPC (TLS CA, `grpc.ssl_target_name_override`=`peerHostAlias`), `Gateway` per identitas di-cache, batas waktu dari config; pesan endorse/submit ditolak → `REJECTED` dengan pesan chaincode (`details[].message`); `UNAVAILABLE`/`DEADLINE_EXCEEDED` sebelum submit → `UNAVAILABLE`; sesudah submit → `COMMIT_UNKNOWN` membawa txId. `qscc.ts`: `GetChainInfo` → decode `common.BlockchainInfo` (`@hyperledger/fabric-protos`) → `height`. `FakeLedger` meniru 8 fungsi chaincode (aturan status, indeks nomor SKPI, kode unit, fakultas NPM, peran per identitas `dekan-<fak>`/`rektor`/`app-reader`) + `setOnline(bool)` + `failNextSubmitWith(kind)`.

- [ ] Test `toApiError`: "Akses ditolak: ..." → 403 FORBIDDEN; "SKPI dengan NPM x tidak ditemukan" → 404; "berstatus AKTIF, seharusnya MENUNGGU_REKTOR" → 409; "Nomor SKPI ... sudah dipakai" → 409; "MVCC_READ_CONFLICT" → 409; "totalSKP 10 tidak memenuhi" → 400; `UNAVAILABLE` → 503 "Layanan ledger sedang tidak terjangkau."; `COMMIT_UNKNOWN` → 503 "Status transaksi belum pasti; sistem akan memeriksanya kembali.". Test FakeLedger: `dekan-ft` memanggil `SahkanDekan` NPM FMIPA → REJECTED "Akses ditolak".
